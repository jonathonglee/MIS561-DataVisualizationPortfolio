In Flex 3, I calculated profit margin in a Tableau calculated field by dividing total profit by total sales; for example, $33,402 in profit on $138,601 in sales across 505 orders gave a 24.10% margin. In Power BI I would build this as a measure rather than a calculated column, because margin is a ratio that has to be recalculated from summed profit and summed sales at whatever level the reader filters to, whereas a column would store a fixed percentage on each order row, and averaging those rows gives the wrong margin by state, subcategory, or year. A measure also stays current when the order data refreshes, so there are no stored values to rebuild each month. For Anita, that means one margin number answers her questions by state, subcategory, and year as she asks them in the meeting, such as Tables falling from -6.83% to -13.49%, without sending me a request to rebuild a view.
